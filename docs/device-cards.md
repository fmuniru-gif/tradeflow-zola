# Registered device cards and Settings stability

Baseline: `9286f24d472dff253b4b69cd1a13ea7a9e950fb9`. Delivery: `20261104-device-cards-r1`.

Self-Service Device Recovery is available to signed-in Owner/Admin staff on initialized registered devices, including paired devices. Disabled staff and known revoked/retired/replaced devices are denied. Only the three local interactive canonical-recovery bridge guards are widened to this registered Owner/Admin predicate; unrelated Owner-only authorities remain unchanged. Fresh canonical Cloud/checkpoint validation, business comparison, paused sync boundary, durable preservation, pending verification and confirmations remain authoritative. No recovery is executed by deploying this change.

Registered devices and Enrolled devices share one read cache scoped to the signed-in staff identity/role, device, business and verified Cloud account. Local Owner/Admin role alone cannot read a paired device's fleet: the existing Owner cloud-account, authenticator, enrolled-fleet and expiring staff-bound management-session verification remains required. Its local staff predicate now accepts registered Owner/Admin users. Reads do not challenge for MFA on every render. Pairing/revocation retain MFA/verified-session requirements and original server authorization. Paired transport credentials are never promoted into an Owner client. Context changes discard stale responses. Self-revocation is blocked, and a changed context invalidates an open revocation dialog before its RPC.

The default directory view shows ACTIVE records reporting this app version and last seen within seven days. A record's last-seen date does not prove it is currently online. The displayed app version is device-reported and cannot certify the latest delivery because existing releases can share that version. Show all device records retains access to older, older-version, inactive and revoked registrations. Filtering and toggling do not revoke, delete, rename or otherwise alter any device. Updating a phone can make its newer presence appear on the next directory refresh.

The two original lists previously used independent queries. The enrollment view scheduled a branch/fleet reload every time Settings rendered, cleared the valid rows to Loading, and replaced the table even when identical records returned. The new consumers share a bounded, business-scoped reader and coalesce automatic loads for 60 seconds. Existing rows remain during refresh; unchanged HTML does not rebuild DOM nodes. Manual Refresh devices forces a fresh read. Filter changes update only directory regions. Scroll position, focused controls and unposted pairing inputs are preserved. No business database, outbox, lifecycle or sync preference is written by directory display or filtering.

## Validation

The real assembled-app test reproduces the prior behavior using an exact-baseline server and disposable authenticated synthetic Owner sessions. Six repeated Settings renders made eight additional legacy directory reads and removed 154 table nodes. The candidate made zero additional reads, removed zero nodes, retained the same row node and preserved scroll, unposted form input, business data and outbox. This establishes a concrete cause of table churn; physical-device scrolling remains to be confirmed.

Other tests cover primary and paired Owner/Admin visibility and local recovery pause, denial for Cashier/Auditor/Read-only users, fresh/current vs historical filtering, shared reads, bad/duplicate directory responses, scoped cache invalidation, Owner-session expiry/staff mismatch, cancelled MFA, denied paired verification and blocked self/unauthorized revocation. Existing canonical-recovery browser tests continue to exercise pending/corrupt locks and queue preservation; their pause fixture now explicitly represents a registered device. All original embedded and standalone business sources remain byte-identical; exact materialization edits and the coupled original Commercial Foundation module are verified by a whole-output equality proof.

The passive delivery pins 86 assets and retains all prior caches and device storage. Source/unit, full Chrome, cached-upgrade, offline/recovery and security regressions run with external networking unavailable. No live fleet record, Supabase schema, business transaction or device recovery is modified by these tests.
