Built on production `a3d30228cfcf2c1577209d779534164bc72452f9` and draft PR17 `c29e4b396dbef367370b3abf834ba36d562add49`. The v3 package is review evidence, not deployment authorization. Its obsolete v2 migration is not used.

This is a **new compensating delivery operation**, not recovery of the missing original sealed operation. The original audit/correction ID and zero-stock layer are preserved. ## Server

The migration pins the existing `zezms_ops_push` body to the Owner-exported definition in `tests/fixtures/m43-server-export.sql` (exports67/69/70). It adds exact-payload comparison before ordinary same-ID ACK and checks owner/correction receipts before processing a duplicate correction. A universal operation-insert trigger also takes the owner state lock and enforces unique `(owner_id,correction_id)`; trigger failure rolls back preceding counter changes. Checkpoint/operation backfill rejects ambiguous identities and conflicting audits. No old RPC is renamed or exposed as a bypass.

An independent M4/3 hash matches the unchanged embedded JS UTF-16 arithmetic, recursive metadata exclusions and JS object-index enumeration. The shared M4/4 canonicalizer/hash are untouched. PostgreSQL JSON cannot represent NUL or unpaired surrogates. The schema71 follow-up replaces the original eight-decimal restriction: the normal correction producer copies complete existing stock rows, including valid floating-point fields. A separate numeric serializer uses pinned PostgreSQL shortest double output with JS decimal/exponent formatting and exact numeric equality to the wire value. Non-JS numeric representations fail instead of rounding stored records or accepting a competing hash. No client or business calculation changes.

The special Owner-only RPC requires one immutable evidence row, provisioned by a separately approved trusted verifier/DB administrator. Authenticated/anonymous clients cannot insert, update or delete evidence or receipts. The **migration provisions no evidence**. A delivery operation cannot attest itself.

That private row binds the exact existing audit, allocation, original timestamp, product, complete independently projected stock-before record, operational period, Main enrollment, business/branch scope and new immutable wire operation. It also binds reviewed archive completeness, checkpoint identity/content SHA-256, owner operation count/content SHA-256, head and state revision, expiry and approval reference. Archived completeness is an independent verifier assertion, not inferred from cursor density/counts. Provisioning an unverified assertion is forbidden.

Under the normal owner state lock, the RPC compares that binding with retained history/checkpoint contents and current revision/head, exact stock/product linkage and counter=2. Only the expected delta-2 existing-row update and insertion of the **same existing audit** are permitted. The ordinary RPC then applies its unchanged protocol/generation/rules/identity/branch checks and counter logic. Counter0, operation and unique receipt commit together. Same-ID retries return the same receipt only after complete payload/hash/audit comparison; a stale head/expired evidence cannot prevent readback of an already accepted identical operation. Revoked/wrong authorization still blocks execution.

## Controlled client

`diagnostics/m43-correction-reconciliation/coordinator.js` is not loaded by the app or worker. It does nothing on import. It provides an explicitly invoked coordinator and browser adapter for a later approved maintenance session. Installed embedded cloud source SHA-256 must match the reviewed build. The original missing envelope is never reconstructed or mislabeled.

Staging requires paused sync, verified Owner scope, no runtime/persisted queued work, matching database copies and exact audit/zero-layer/product equality. It writes a checksummed private maintenance stage before reserving one device sequence. The embedded save/readiness/transport guards hold normal posting and sync while the stage exists. Restart must load that reservation before delivery. Ordinary changes, corrupt evidence or unexpected queues hold execution; nothing is discarded.

The exact same staged operation survives timeout, lost ACK and restart. Capability checks still run. Independent operation/receipt readback must match owner, ID, hash, audit and server sequence. Finalization changes only the applied-operation register and this tool's own receipt/stage metadata; it never jumps the cursor or changes business records. Restart is required before normal sync resumes. A storage failure retains the stage for same-ID verification; no new identity is minted.
