# Main cash projection recovery

The reviewed private r2 report binds one original Main operation at server sequence4293. Its cash-log entry and wallet deduction are missing from Main although Cloud accepted the original operation and Main recorded it as applied. This tool restores the existing local effects; it never posts a new cash transaction or retries the operation.

Production pins the SHA-256 of that exact private report. The Owner selects the same downloaded JSON locally. A fresh preview authenticates Main's saved Cloud Owner, verifies the checkpoint, ordered history, source-operation SHA/hash/identity, applied register, currency values and local stability. It accepts only the original record and the original wallet's exact before/after values. The prospective complete business state must match Cloud after narrowly checked representation normalization: the report-bound security/version pair, empty management initialization, native-certified undo product-ID metadata, and report-bound registered numeric-zero wallet keys. Raw Main data outside the original entry and that wallet value remain byte-for-byte equivalent under an exact inverse-scope assertion. Orphan sets must match Cloud; the tool retains warnings.

The write requires a single service-worker-attested TradeFlow client, a Web Lock, a fresh three-minute preview, offline state, the active local Owner password, an acknowledgement and an explicit confirmation of the actual entry and wallet values. It first commits and reads back the exact original DB/state in a separate IndexedDB rollback archive, then durably pauses Live Sync before one DB write. The primary auth, queue, applied register, cursor/sequence, staff access, existing archives and all other localStorage keys are preserved. Archive/pause failures prevent the DB write; DB-write failures retain the original or its verified archive while paused. Receipt-write failure reports the already completed data write honestly and keeps Main paused for review. Already restored effects are not applied twice.

After verified completion, download the receipt, close this page, restore internet, reopen Main and explicitly Enable Live Sync through normal protocol gates. This tool does not change the normal app/worker/manifest/delivery or repair the shared orphan references.

Validation uses synthetic data only, including real browser crypto, localStorage and IndexedDB. Runtime tests inject a synthetic reviewed-report digest through the exported UI factory; a separate exact-production-entry test verifies that its fixed private-report digest rejects an unreviewed file before reads/writes. Scope, provenance, complete-state comparison, idempotence, Owner password, offline/expiry/other-client guards, archive/pause/DB/receipt failure paths and invariants are tested in loopback-only CI. No automated test accesses a real device or production database.
