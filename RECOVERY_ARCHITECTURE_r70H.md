# r70H architecture

The local `deviceId` is a pointer, not proof that the physical device is new. If its exact active-context lookup fails while an anonymous PAIRED session survives, r70H first makes a read-only, no-argument self-binding request. The server derives only from `auth.uid()` and requires active, agreeing access/lifecycle/registered-device/business/branch records. It returns no fleet and cannot mutate identity. A valid result restores only the local PAIRED pointer and then uses normal presence and narrow staff recovery. An unknown anonymous session is never allowed to call the Owner fleet reader; it is directed to temporary Owner MFA verification first. An Owner/Admin session can read eligible ACTIVE records for its current business, explicitly select one, and have the server verify it under AAL2.

For a genuinely necessary PAIRED Owner-selected relink, the server verifies the same existing lifecycle/access/registry binding and replaces only its anonymous `device_user_id`; r70H adopts and verifies that exact session before it changes the local pointer. OWNER records keep (or deliberately adopt) the verified Owner session. Business roots, queue, cursor and failed count are checked around every relink. If presence or staff-directory recovery fails, the prior session, identity bindings, pointer fields (including `r70hRelinkLifecycleId`) and local DB snapshot are restored. A self-binding recovery does not change its already-correct anonymous session. The staff recovery hydrates only `sharedDeviceDirectory` and `sharedDeviceAuth`.

Presence is one resolver-protected normal control-plane update. The M5A3 compatibility context now forwards its supplied running version into it after existing M5A4 validation. For the one Owner-selected relink case, the same update is additionally bound to that selected lifecycle and requires AAL2. It updates matched existing access, registered-device and lifecycle metadata with device name, platform, running version and current last-seen time. It never inserts a registered row or lifecycle.
